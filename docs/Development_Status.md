# CtoN 开发进展与项目状态

最后更新：2026-08-23

## 1. 最终目标

CtoN 的产品目标是让访客通过一个稳定的公开域名直接访问网站，在同一体验中浏览重庆至南京高铁沿线的地图、天气、气象剖面、随机旅途、城市诗句和全线路建议。

当前目标已经以 Vercel 正式域名实现：

```text
https://cton-frontend.vercel.app
```

这个域名是唯一的访客入口。浏览器通过同源 rewrite 访问后端，不需要知道后端地址，也不接触任何管理凭据。

## 3. 生产基线

### 公开入口

- 前端：<https://cton-frontend.vercel.app>
- 后端健康检查：<https://cton-backend.vercel.app/api/v1/health>

后端正式域名用于运维和前端 rewrite，不应作为访客入口宣传。

### 部署拓扑

同一个 GitHub 仓库连接两个 Vercel Project：

| Project | Root Directory | 作用 |
|---|---|---|
| `cton-backend` | 仓库根目录 | FastAPI、Cron、高德安全代理 |
| `cton-frontend` | `frontend` | Vite 静态站点和同源 rewrite |

Neon 提供两类数据库地址：

- 池化地址保存为后端 Production `DATABASE_URL`，供函数运行；
- 非池化直连地址仅在受控的本地初始化或结构维护中临时使用，不保存到 Vercel。

### 已完成的上线验收

- 后端测试曾实际得到 `135 passed in 2.73s`；
- 前端 6 个测试文件、31 项测试通过，生产构建通过；
- 城市切换会保留旧图至目标天气图就绪，显示沿线列车加载状态并交叉淡化；连续切换、备用图与错误回退已测试；
- 前端域名下的首页、健康检查、八站路线、随机旅途和建议读取正常；
- 未携带管理员令牌的写接口返回 `401`，正确令牌可更新天气和建议；
- 八座城市的天气与空气质量请求均返回成功，DeepSeek 建议生成成功；

- Cron 路径为 `/api/v1/internal/daily-update`，计划为 `0 22 * * *`；

## 4. 仍需持续观察的事项

以下事项不阻塞当前网站访问，但属于后续维护工作：

1. 在首次自然调度后检查 Cron 日志。Hobby 计划会在每天 UTC 22:00 所在小时执行，即北京时间约 06:00–06:59。
2. 在 Neon 当前套餐允许的范围内完成一次时间点恢复分支演练，并记录恢复结果。
3. 核对后端 Project 是否已为 `/_AMapService/*` 配置合适的 Rate Limit；根据真实访问日志调整阈值。
4. 持续观察 Vercel 函数耗时、Neon 连接数以及第三方 API 配额。
5. 从不同中国内地网络继续抽样验证静态资源、API 和地图加载体验。

## 5. 当前产品边界

- 目前只有重庆至南京一条固定线路和八个城市站点；
- 动态数据是按业务日期保存的天气快照，不是专业预报或预警服务；
- 旅途建议由模型生成，并经过长度和内容结构校验，但仍只用于旅行参考；
- Vercel Hobby Cron 每天运行一次，执行时间存在最多约一小时的浮动；
- 项目依赖和风天气、高德地图、DeepSeek、Neon 和 Vercel 的可用性与配额。

## 6. 如何维护这份状态

每次发布后只记录实际验证过的结果，不用配置文件推断云端已经成功：

1. 更新“当前阶段”和生产基线提交；
2. 把新完成的验收加入“已完成”；
3. 把未验证、待观察或受外部条件限制的内容保留在“仍需持续观察”；
4. 若生产域名、架构、环境变量或发布流程变化，同时更新 `README.md`、`AGENTS.md` 和 `docs/Production_Deployment.md`。
